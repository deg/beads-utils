## Unreleased

* [fix] `bd-view` no longer drops fields that `bd show` renders: the `metadata` dict, `labels`, `external_ref`, `spec_id`, `defer_until`, and the parent/children relationships (previously folded into "Depends on:" / "Blocks:" because the `dependency_type` on each edge was ignored). Dependencies are now grouped by that type — `Parent:`, `Children:`, `Depends on:`, `Blocks:`, plus the rarer `tracks` / `discovered-from` / `supersedes` / … kinds — with unknown types rendered under their raw name. To keep this from recurring, unclaimed top-level JSON keys land in a trailing `Other Fields` section (mirroring `bd show --long`'s own `EXTENDED DETAILS`), so a column `bd` adds later shows up unprompted instead of vanishing. The `rich`-less plain-text fallback renders the same field set.
* [feature] `bd-dolt-diff` — preview what a `bd dolt push` would actually send. Where `bd-dolt-check` answers "am I in sync?", this answers "in sync with what, exactly?": an issue-level diff between the remote-tracking ref and your local branch, showing added/removed issues and field-level before/after for changed ones, plus dependency, label, and comment changes. `--base`/`--head` diff any two Dolt revisions (e.g. against a pre-migration branch). Read-only; exits 0 whenever the comparison ran, so `bd-dolt-check` remains the CI gate. Two design details worth knowing: dependency and comment rows are keyed on their semantic tuple rather than their surrogate `id`, because Dolt assigns a fresh `uuid()` per insert and the same logical edge created on two clones would otherwise show as a spurious add+remove pair; and when a schema migration means the two revisions don't share a column set, the diff falls back to the intersection and names the skipped columns instead of failing (selecting a column absent from one side is a hard error in Dolt).
* [refactor] Dolt/git plumbing shared by the Dolt-aware scripts (`run`, `strip_ansi`, `have_dolt`, `read_metadata`, `locate_dolt_db`, `read_repo_state`, `get_head_branch`, `read_dolt_remotes`, `get_git_remote_url`, `dolt_fetch`, `dolt_rev`, `dolt_count_range`) moved from `bd-dolt-check` into `bdutils`, joined by new `dolt_log_range`, `dolt_sql_json`, and `dolt_table_columns` helpers. `bd-dolt-check` imports them instead of defining its own; its output is byte-identical. `get_remote_url` is now `bdutils.get_git_remote_url` and `_have_dolt` is now the public `bdutils.have_dolt`.
* [feature] `claude-session-list` — git-log-style listing of recent Claude Code sessions. Defaults to cwd's project; `-g/--global` spans all. `--oneline` for one-per-row, `-q/--quiet` for UUIDs only (pipe-friendly for `claude --resume`). Shows timestamp range, age, prompt/reply counts (`N prompts / M replies` in block view, `Np/Mr` in oneline), and title.
* [feature] `claude-session-list` filters truly-empty sessions (e.g. `/clear`-ghost sessions where `0p/0r`) by default; `-a/--all` shows everything, `--min-prompts N` is a stricter filter. Hidden count reported to stderr (suppressed in `-q` so pipes stay clean). The prompt counter strips wrapper tags (`<command-name>`, `<system-reminder>`, `<local-command-caveat>`, `<bash-input>`, …) so entries that are pure plumbing don't count as human prompts.
* [feature] `claude-session-list --oneline` now emits an `ID / STARTED / AGE / COUNTS / PROJECT / TITLE` header row and sizes the COUNTS and PROJECT columns to fit the actual data — no more title-column jitter when a project name like `marketbuzzr_landing_page` shows up under `-g`. STARTED is the session's first timestamp (when the conversation began); AGE is time since the last activity. `-q` continues to skip the header (pipe-friendly).
* [feature] `claude-session-list -s/--sort=KEYS` — comma-separated sort keys with `-` prefix for descending. Keys: `started`, `last`, `duration`, `prompts`, `replies`, `turns`, `title`, `project`, `id`. Default order unchanged (newest activity first).
* [feature] `claude-session-list -m/--match=PATTERN` — case-insensitive substring filter against title OR full UUID.
* [breaking] `bd-export-csv --sortby` renamed to `-s/--sort` to align with `claude-session-list` and the GNU coreutils convention (`ls --sort`, `ps --sort`). Semantics unchanged: comma-separated keys, `-` prefix for descending.
* [refactor] Session enumeration helpers (`iter_sessions`, `list_sessions`, `resolve_session`, project-dir lookup) moved from `claude-session-report` into a new shared `claudeutils` module. `bd-complete sessions` now imports the helper directly instead of shelling out.
* [breaking] Removed `claude-session-report --list-sessions` — its only consumer was `bd-complete`. `claude-session-list -g -q` is the user-facing replacement; `bd-complete sessions` is unaffected.
